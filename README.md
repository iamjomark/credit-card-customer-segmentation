# Customer segmentation of credit card holders (unsupervised learning)

## Business question

Which groups of credit card customers exist, based on how they spend, pay and borrow, and what does each group look like in business terms?

## Data

The **CC GENERAL** credit card dataset: 8,950 customers, 18 columns, behaviour over the last 6 months (balance, purchases, cash advances, payments, credit limit, tenure). `CUST_ID` is dropped, and a few values are missing in `MINIMUM_PAYMENTS` (313) and `CREDIT_LIMIT` (1).

The data is **not stored in this repository** (see `.gitignore`). To run the project, save the CSV as `data/raw/credit_card.csv`.

## How to run

You need [uv](https://docs.astral.sh/uv/) and Python 3.12 or newer (the project pins 3.12).

```bash
uv sync
```

```bash
uv run jupyter lab
```

Then run the notebooks **in order**. Each one saves files that the next one reads from `data/processed/`:

| Notebook | What it does | Saves |
|---|---|---|
| `notebooks/01_eda.ipynb` | Profiling report, univariate EDA, normality tests, Spearman correlation, missing values, outliers (Steps 1 to 4) | `reports/credit_card_profile.html`, figures |
| `notebooks/02_preprocessing.ipynb` | Compares transforms, builds the preprocessing pipeline, PCA (Steps 5 and 6) | fitted pipeline and scaled data |
| `notebooks/03_clustering.ipynb` | KMeans k=2 to 10, metrics, stability, GMM and Agglomerative comparison, robustness checks, cluster profiles (Steps 7 and 8) | cluster labels, model, names |
| `notebooks/04_explainability.ipynb` | Surrogate model, SHAP, distance contributions, permutation importance (Step 9) | figures |

To run everything from the command line instead:

```bash
for notebook in 01_eda 02_preprocessing 03_clustering 04_explainability; do uv run jupyter nbconvert --to notebook --execute --inplace notebooks/$notebook.ipynb; done
```

The notebooks are generated by the small scripts in `scripts/` (so interpretation text is written after the results are read). You do not need them to run the project.

## Key results

- **Six segments** (k=6), chosen on stability and usefulness (the usual score-based measures were flat). The groups reappear almost unchanged on resampled customers (agreement score 0.976).
- **Silhouette is about 0.22**, which is low: customers form a continuous range, so segment boundaries are soft.
- A **surrogate Random Forest** predicts a customer's segment from their features with **95.0% accuracy** on unseen customers, and SHAP, distance contributions and permutation importance agree on what defines each segment.

| Segment | Share |
|---|---|
| Cash advance borrowers | 26.9% |
| Steady everyday spenders | 22.9% |
| Big spenders, high limit, carry a balance | 18.3% |
| Frequent buyers, pay in full | 13.9% |
| Dormant, barely used card | 11.3% |
| Newer customers, small limit, mixed use | 6.6% |

**Read the business summary, limitations and next steps here: [reports/business_summary.md](reports/business_summary.md).**

## Caveats

- The segmentation is sensitive to how skewed data is transformed (using Yeo-Johnson instead of log1p changes the groups noticeably, agreement 0.67).
- No revenue, default or demographic data was available, so the segments describe behaviour only.
